init_db.py

Create this file in sqli-lab/. This creates our database and adds test users to it.

import sqlite3
import os

DB_PATH = os.path.join("instance", "users.db")
os.makedirs("instance", exist_ok=True)

conn = sqlite3.connect(DB_PATH)
cur = conn.cursor()

cur.execute("""
CREATE TABLE IF NOT EXISTS users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    username TEXT NOT NULL UNIQUE,
    password TEXT NOT NULL
)
""")

# Clear old data for repeatable demos
cur.execute("DELETE FROM users")

# Seed a known user
cur.execute("INSERT OR IGNORE INTO users (username, password) VALUES (?, ?)", ("admin", "supersecret123"))
cur.execute("INSERT OR IGNORE INTO users (username, password) VALUES (?, ?)", ("test", "password123"))

conn.commit()
conn.close()

print(f"[+] Database initialized at {DB_PATH}")
print("[+] Users created: admin / test")

Explanation: This creates a table called users with id, username and password. It creates two test accounts for us to use.

app.py

Create this file in sqli-lab/. This is our web application.

import os
import sqlite3
from flask import Flask, render_template, request

app = Flask(__name__)
DB_PATH = os.path.join("instance", "users.db")

@app.route("/", methods=["GET", "POST"])
def login():
    error = None
    query_shown = None

    if request.method == "POST":
        username = request.form.get("username", "")
        password = request.form.get("password", "")

        conn = sqlite3.connect(DB_PATH)
        cur = conn.cursor()

        query = f"SELECT id, username FROM users WHERE username = '{username}' AND password = '{password}'"
        query_shown = query

        try:
            cur.execute(query)
            user = cur.fetchone()
        except Exception as e:
            error = f"SQL Error: {e}"
            user = None
        finally:
            conn.close()

        if user:
            return render_template("login.html", success=f"Logged in as {user[1]} (id={user[0]})", query=query_shown)
        else:
            if not error:
                error = "Invalid username or password."
            return render_template("login.html", error=error, query=query_shown)

    return render_template("login.html")

if __name__ == "__main__":
    # Only for local testing
    app.run(debug=True)

Exploiting our Application

Prediction Exercise

Before trying any payload, answer this to yourself.

If I type test as the username and password123 as the password, what would the query look like based off of app.py’s vulnerable line?

Take a look back at the line: f"SELECT id, username FROM users WHERE username = '{username}' AND password = '{password}'"

With test and password123 it would become:

SELECT id, username FROM users WHERE username = 'test' AND password = 'password123'

This matches! The single quotes are added by our code, and our input goes inside of them. This is the key.

Exploit 1: Comment out the rest of the query (--)

The SQL comment -- will tell the database to ignore everything after it on that line.

  1. Go to the login page.
  2. For Username, type: admin' --
  3. For Password, type: anything (it doesn’t matter, it will be commented out!)
  4. Click Login

Observe

Look at the query box. It should look something like this:

SELECT id, username FROM users WHERE username = 'admin' -- ' AND password = 'anything'

See what happened? Our input injected admin' which closed the username’s quote, and -- commented out AND password = '...'. The password check has been completely removed! Because of this, we are logged in as admin without knowing the password.

What happened (Breakdown)

  • Original structure: WHERE username = '...input...' AND password = '...input...'
  • We made it: WHERE username = 'admin' followed by a comment, so the AND password = ... is ignored by the database.

Exploit 2: Make the condition always true (OR '1'='1')

This is one of the most famous payloads. '1'='1' is always true in SQL.

  1. Clear the form (refresh the page)
  2. For Username, type: ' OR '1'='1' --
  3. For Password, type: anything
  4. Click Login

Observe

Your query should look similar to this:

SELECT id, username FROM users WHERE username = '' OR '1'='1' -- ' AND password = 'anything'

The WHERE clause is now (username = '') OR ('1'='1'). '1'='1' is always true, so this condition is true for at least the first row that it finds. Depending on how the database returns it, this will often log us in (in this case it will authenticate as a user).

What happened (Breakdown)

  • We closed the quotes with ', added OR '1'='1' which makes the logic always evaluate to true.
  • We commented out the rest with -- to ignore the password check entirely.

Breaking It V1

Bypass it (maybe that was a bad fix)

Try obfuscating the OR. For example:

' oR '1'='1

Further reasons why that is a bad fix

  • There are infinite payloads. An attacker can find any variation to bypass a blacklist.
  • False positives: If a legitimate user had or in their password (uncommon, but possible), they would be blocked.
  • Obfuscation: Comments /**/, encoding, or different syntax can all be used to bypass it.

This is security through obscurity. It is trivial to get around with enough effort.

Undo your changes

Before moving onto the correct fix, revert app.py back to its original vulnerable state (the one from Chapter 2) or just remove the “fixes” that we just added. We will be replacing the logic entirely in the next chapter.

Fixing It v2 (Parameterized Queries)

Now that we’ve proven why the incorrect fix failed, we’ll apply the correct, robust fix. This is the standard that should be used in any application that talks to a database.

Important

The fix is to stop concatenating user input into the query and instead, pass it separately to the database driver to be safely parameterized.

The Fix

We will be using sqlite3’s ? placeholder for parameterized queries.

Change app.py

Replace the entire vulnerable login logic with this correct version.

import os
import sqlite3
from flask import Flask, render_template, request

app = Flask(__name__)
DB_PATH = os.path.join("instance", "users.db")

@app.route("/", methods=["GET", "POST"])
def login():
    error = None
    query_shown = None

    if request.method == "POST":
        username = request.form.get("username", "")
        password = request.form.get("password", "")

        conn = sqlite3.connect(DB_PATH)
        cur = conn.cursor()

        # CORRECT: Use parameterized queries (prepared statements)
        # The SQL structure is fixed. User input is passed as data.
        query = "SELECT id, username FROM users WHERE username = ? AND password = ?"
        query_shown = query  # For learning purposes only, no user input is concatenated here

        try:
            # Pass the values as a tuple. The driver safely handles them.
            cur.execute(query, (username, password))
            user = cur.fetchone()
        except Exception as e:
            # For a lab this is okay to show, however see Chapter 9 for production advice
            error = f"SQL Error: {e}"
            user = None
        finally:
            conn.close()

        if user:
            return render_template("login.html", success=f"Logged in as {user[1]} (id={user[0]})", query=query_shown)
        else:
            if not error:
                error = "Invalid username or password."
            return render_template("login.html", error=error, query=query_shown)

    return render_template("login.html")

if __name__ == "__main__":
    # Only for local testing
    app.run(debug=True)

What’s different?

VulnerableCorrect
query = f"... '{username}' ... '{password}' ..." and cur.execute(query)query = "... ? ... ?" and cur.execute(query, (username, password))
User input is glued into the SQL string.User input is sent separately as parameters. The database treats it as data, not code.
Attackers can change the query’s structure.The query’s structure is fixed. No matter what characters are put in, they cannot alter WHERE, add OR, or add comments to change logic.

Hardening and Best Practices

Parameterization fixes SQL Injection. However, a real login system needs more layers of defense. Here are beginner-friendly best practices to be aware of for future projects.

Note

We won’t be implementing all of these into this lab (as to not overcomplicate it), however it’s critical to know about them.

PracticeWhy?Beginner Example
Hash passwordsIf your database ever gets leaked, plain text passwords are exposed to everyone.Use werkzeug.security.generate_password_hash() and check_password_hash() when storing and verifying passwords.
Don’t leak SQL errorsShowing SQL Error: ... to users can reveal information about your database structure (table names, schema, etc) to attackers.Log the error to your server console, and show a generic error to the user (e.g “Something went wrong. Please try again.”).
Use the principle of least privilegeThe database user that your app connects with should only be able to do what it needs to do.If your app only needs to read users for login, don’t give it permission to DELETE, DROP TABLE, or create users.
Rate limitingPrevents brute force attacks where someone tries to guess passwords over and over again.Tools like Flask-Limiter can limit how many login attempts a user/IP can make within a time window.
Use ORMsObject Relational Mappers (like SQLAlchemy) use parameterized queries by default and make it much harder to accidentally concatenate.Great “next step” once you’re more comfortable with Python and SQL.
Consider MFAMulti-Factor Authentication adds another layer of security even if a password is guessed or leaked.Beyond the scope of this lab, but incredibly important.

import os

conn = sqlite3.connect(DB_PATH)
cur = conn.cursor()

cur.execute("""
CREATE TABLE IF NOT EXISTS users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    username TEXT NOT NULL UNIQUE,
    password TEXT NOT NULL
)
""")

cur.execute("DELETE FROM users")

cur.execute("INSERT OR IGNORE INTO users (username, password) VALUES (?, ?)", ("admin", "supersecret123"))

conn.close()

sqli-lab/app.py (Vulnerable - For learning only)

import os
import sqlite3
from flask import Flask, render_template, request

app = Flask(__name__)
DB_PATH = os.path.join("instance", "users.db")

@app.route("/", methods=["GET", "POST"])
def login():
    error = None
    query_shown = None

    if request.method == "POST":
        username = request.form.get("username", "")
        password = request.form.get("password", "")

        conn = sqlite3.connect(DB_PATH)
        cur = conn.cursor()

        query = f"SELECT id, username FROM users WHERE username = '{username}' AND password = '{password}'"
        query_shown = query

        try:
            cur.execute(query)
            user = cur.fetchone()
        except Exception as e:
            error = f"SQL Error: {e}"
            user = None
        finally:
            conn.close()

        if user:
            return render_template("login.html", success=f"Logged in as {user[1]} (id={user[0]})", query=query_shown)
        else:
            if not error:
                error = "Invalid username or password."
            return render_template("login.html", error=error, query=query_shown)

    return render_template("login.html")

if __name__ == "__main__":
    app.run(debug=True)

sqli-lab/app.py (Fixed - Correct)

import os
import sqlite3
from flask import Flask, render_template, request

app = Flask(__name__)
DB_PATH = os.path.join("instance", "users.db")

@app.route("/", methods=["GET", "POST"])
def login():
    error = None
    query_shown = None

    if request.method == "POST":
        username = request.form.get("username", "")
        password = request.form.get("password", "")

        conn = sqlite3.connect(DB_PATH)
        cur = conn.cursor()

        query = "SELECT id, username FROM users WHERE username = ? AND password = ?"
        query_shown = query

        try:
            cur.execute(query, (username, password))
            user = cur.fetchone()
        except Exception as e:
            error = f"SQL Error: {e}"
            user = None
        finally:
            conn.close()

        if user:
            return render_template("login.html", success=f"Logged in as {user[1]} (id={user[0]})", query=query_shown)
        else:
            if not error:
                error = "Invalid username or password."
            return render_template("login.html", error=error, query=query_shown)

    return render_template("login.html")

if __name__ == "__main__":
    app.run(debug=True)

Troubleshooting

IssuePossible CauseFix
python or py not foundPython not installed or not added to PATH (Windows)Reinstall Python and check Add python.exe to PATH. Try py on Windows, python3 on macOS/Linux.
Can’t activate venv on Windows (script execution disabled)PowerShell’s execution policy is blocking scriptsOpen PowerShell as your user and run: Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser. Then try activating again. Only do this for your user account.
ModuleNotFoundError: No module named 'flask'Virtual environment not activated, or packages not installedActivate your venv ((.venv)) and run pip install -r requirements.txt again.
Port 5000 already in useSomething else is running on port 5000Close the other program, or run Flask on a different port: flask run --port 5001. Remember to go to the new port in your browser.
Database errorsCorrupted or missing databaseDelete instance/users.db and run python init_db.py again.
Page doesn’t load / connection refusedServer not runningMake sure the terminal with python app.py is still running and hasn’t crashed. Check for errors in that terminal.
Changes aren’t showing upBrowser cache or server not restartedHard refresh your browser (Ctrl+Shift+R or Cmd+Shift+R). If you changed app.py, restart the server with Ctrl+C and python app.py again.
Quotes being weird when copying payloadsSmart quotes from some documentsAlways type the payloads exactly as shown in the book. Avoid copying from rich text documents, copy from the code blocks.

Key Takeaway

# VULNERABLE
query = f"SELECT ... WHERE username = '{username}' ..."
cur.execute(query)

# SECURE
query = "SELECT ... WHERE username = ? AND password = ?"
cur.execute(query, (username, password))

Rule of thumb: If you ever find yourself using f-strings or string concatenation to build SQL with user input, stop and use parameterized queries instead.
